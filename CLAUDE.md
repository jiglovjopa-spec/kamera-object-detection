# CLAUDE.md — «Камера: предметы, номера, овощи»

Контекст для Claude Code. Пользователь — руководитель/инженер, не программист: общаемся **по-русски**,
простыми словами, весь интерфейс и сообщения — на русском. Это **отдельная программа**, не часть
«Операционного пульта» (`..\pult`) — их код и данные не смешивать.

## Что это

Настольная программа для Windows: веб-камера ноутбука → в реальном времени рамки и русские подписи:
предметы (365 видов), овощи (23 вида), российские автомобильные номера (поиск + чтение текста, журнал со снимками).
Всё локально, после установки работает **без интернета** (проверено запретом сокетов: 0 попыток соединения).
Распознавания лиц нет и не планировалось.

Пользовательская инструкция, ограничения и лицензии — в `README.md` (держать в актуальном состоянии).

## Стек

- Python 3.14, окружение `.venv` (создаёт `Запустить камеру.bat`; привязано к Python этого ПК).
- onnxruntime-gpu + библиотеки NVIDIA CUDA 13 / cuDNN из pip (`ort.preload_dlls()`), OpenCV, Pillow, Tk.
  Без NVIDIA — само переходит на процессор (медленно: предметы ~0,6 раз/с).
- `open-image-models==0.6.0` ставится **с `--no-deps`** (нужен только `YoloV9Detector`); его зависимости
  (huggingface_hub, tokenizers…) не нужны — не добавлять.
- Версии закреплены в `app\requirements.txt`. Без PyTorch: обучение делалось отдельно, программе он не нужен.

## Структура

```
Запустить камеру.bat   точка входа: проверка окружения → создание .venv + pip → setup_models.py → main.py %*
                       (CRLF, UTF-8 без BOM, chcp 65001 — иначе cmd ломает кириллицу)
app\main.py            окно Tk: поток камеры (CAP_DSHOW, MJPG 1280×720, переподключение каждые 3 с),
                       два потока-распознавателя (предметы+овощи, номера), список номеров, статус
app\detectors.py       SceneDetector (D-FINE + определитель овоща), PlateDetector (YOLOv9) + PlateReader
app\plates.py          PlateTracker (номер подтверждается 3 одинаковыми чтениями) и PlateJournal (CSV + снимки)
app\russian_plate.py   разбор вывода модели по шаблонам LDDDLLDD / LDDDLLDDD, латиница→кириллица
app\labels.py          русские названия 365 классов Objects365, кандидаты в овощи, NOT_VEGETABLES (фрукты)
app\setup_models.py    докачивает открытые модели, если их нет; свои модели только проверяет
models\                все модели (~300 МБ). Две свои скачать неоткуда — папку беречь и переносить целиком
обучение\              скрипты обучения своих моделей (для истории; данных и PyTorch-окружения больше нет)
результаты\            журнал_номеров.csv (utf-8-sig, «;») и снимки\ — данные пользователя, создаются при работе
```

## Модели

| Файл | Что | Примечание |
|---|---|---|
| `dfine-l-obj365.onnx` | D-FINE-L, Objects365 | вход 640×640 RGB/255 без нормализации, sigmoid по логитам, класс 0 = «None» |
| `yolo-v9-s-608-license-plates-end2end.onnx` | поиск номера | YOLOv9 — GPL-3.0 (пользователь предупреждён, внутреннее использование) |
| `ru-plate-reader.onnx/.json` | своя PlateNet, серый 64×192, 9 позиций × 23 символа | обучена на AUTO.RIA (CC BY 4.0), 49 тыс. номеров |
| `vegetable-classifier.onnx/.json` | свой EfficientNet-B0, 224, норм. ImageNet, 24 класса вкл. «другое» | дообучен с порчей «как веб-камера» и кухонными снимками omorros (чётные id) |

## Грабли (важно)

- **DirectML даёт неверные ответы** на D-FINE (GridSample) — только CUDA или процессор.
- Определитель овоща обучался на чистых фото: на веб-камере бледное яблоко принимал за картофель (0,83).
  Лечение — дообучение (`обучение\train_veg2.py`) + правило: если D-FINE видит фрукт, переубедить
  можно только с уверенностью ≥ 0,85 (`fruit_override_threshold`). Пороги подбирались на выгрузке решений.
- Независимой проверкой овощей служат **нечётные** снимки omorros/kitchen (чётные ушли в обучение).
  Набор Nattakarn/cc92 для проверки не годится — из него же обучение.
- `cv2.imwrite` не пишет в кириллические пути — `imencode` + `write_bytes`.
- Журнал может быть открыт в Excel → запись откладывается (`PlateJournal.pending`), окно не должно падать;
  любое исключение в `tick()` ловится, иначе Tk перестаёт обновлять кадр.
- Видеопамяти 4 ГБ: обучение шло с batch 128; во время обучения на GPU не запускать другое.
- Не путать `CUDA_VISIBLE_DEVICES=-1` (проверка режима процессора) с реальной ошибкой: ORT пишет EP Error и сам переходит на CPU.

## Git / GitHub

Публичный репозиторий. В git **нет** открытых моделей (`.gitignore`: D-FINE 120 МБ больше лимита GitHub,
YOLOv9) — их качает `setup_models.py` (проверено: скачанные файлы побайтно совпадают). Свои две модели — в git.
`.gitattributes` держит `.bat` в CRLF. Не коммитить `.venv`, `результаты\` (журнал и снимки с номерами машин).

## Как проверять

- Без камеры: `Запустить камеру.bat --source фото.jpg --exit-after 15 --screenshot итог.png`
  (печатает строки `ВИДЕЛ` и `ИТОГ` со скоростью и ошибками; сохраняет кадры `_овощ`/`_номер`).
- Камера: то же без `--source`. Перед включением камеры предупреждать пользователя; кадры с людьми
  после проверки удалять, в отчёт не тащить.
- Проверочные записи в `результаты\` после тестов удалять — это журнал пользователя.

## Измерено (ноутбук i5-10300H, GTX 1650 4 ГБ, ноябрь 2026)

- Видео ~20 кадров/с, рамки предметов/овощей 8–10 раз/с, номера 8–10 раз/с.
- Номера: тест AUTO.RIA 99,75%; ширина ≥70 пикс — ~99%, 55 — 91%, 40 — 26%; на 199 фото Викисклада
  из 46 уверенных чтений 1 ошибка (казахстанский номер); на живой камере номер с телефона прочитан верно.
- Овощи (нечётные кухонные снимки): 94% чётко, 81% смазано; фрукт назван овощем 1–2 из 119.
- **Не проверено вживую:** настоящий овощ перед камерой и яблоко после дообучения.
